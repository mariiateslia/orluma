# Security

Orluma v0.1 is an early self-hosted release. Deploy behind HTTPS, bootstrap the first account before public exposure, retain invite-only registration, restrict database/backup access and keep dependencies updated. Read docs/SELF_HOSTING.md before inviting a real team.

Please use the repository’s **Security → Report a vulnerability** private reporting feature. If it is unavailable, open a minimal issue asking for a private reporting channel without including exploit details or private data. Do not post databases, session cookies, passwords or active invitation links in public issues.

Reports are welcome for cross-workspace access, role escalation, unsafe authentication/session handling, injection, data loss and financial state inconsistencies. Include a reproduction using synthetic accounts and data. No response-time or bug-bounty commitment is made.

Owners/admins can read full financial records. Members can read only their own spending requests and linked expenses; viewers have no financial access. General tasks and documents are shared. Report any API response, activity event, comment path or export that bypasses this model.
