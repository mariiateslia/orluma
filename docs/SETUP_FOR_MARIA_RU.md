# Что понадобится от Марии для первой онлайн-беты

Адрес приложения: **https://orluma.mariateslia.site**. Локальная версия и тесты работают без внешних аккаунтов. Публичный сервер ещё не создан; платные тарифы не подключены.

## Render — сервер и база данных

[Создать аккаунт Render](https://dashboard.render.com/register). Удобно войти через GitHub `mariiateslia`. Когда перейдём к публикации, дать Render доступ только к репозиторию `mariiateslia/orluma`.

Render будет запускать Node/Express и хранить PostgreSQL. Пользователи Orluma не создают аккаунты Render: это инфраструктура владельца установки.

Настройки для последующего подключения:

- Web Service из проверенной ветки; Node.js 24.
- Build: `npm ci && npm run build`; Start: `npm start`.
- Health Check: `/api/health`.
- PostgreSQL 17 и приложение — в одном регионе США; выберем доступный регион вместе при создании.
- Приложение использует внутренний `DATABASE_URL` Render. Закрываем ненужный внешний доступ к базе.
- `HOST=0.0.0.0`, `NODE_ENV=production`, `TRUST_PROXY=1` при единственном доверенном прокси Render.
- `APP_URL=https://orluma.mariateslia.site`.
- `REGISTRATION_MODE=invite`; `BOOTSTRAP_EMAIL` — твой email для первого входа.
- Постоянный случайный `AUTH_SECRET`, а также ключ почты — в секретах сервиса, вне GitHub.

**Пока достаточно зарегистрироваться и подтвердить email.** Перед созданием платной базы/сервера нужно увидеть итоговую цену и ограничения выбранного тарифа. Стоимость зависит от тарифа, диска, хранения резервных копий и трафика; это не бесплатный безлимитный хостинг.

Официальная документация: [Node/Express на Render](https://render.com/docs/deploy-node-express-app), [PostgreSQL и подключения](https://render.com/docs/postgresql-creating-connecting).

## Resend — письма Orluma

[Создать аккаунт Resend](https://resend.com/signup) и подтвердить email. Этот сервис доставляет подтверждение регистрации, восстановление пароля и приглашения. Авторизация пользователей работает в самом Orluma через Better Auth; отдельный аккаунт Better Auth не нужен.

После регистрации:

1. Добавить отправляющий поддомен **auth.orluma.mariateslia.site**. Он отделён от адреса приложения.
2. В DNS добавить ровно те DKIM/SPF-записи, которые покажет Resend. Не удалять существующие почтовые записи основного домена и не придумывать значения вручную.
3. Дождаться статуса Verified. Для этих писем отключить open/click tracking.
4. Создать ключ только для отправки писем, по возможности ограниченный этим поддоменом.
5. В секретах сервера задать `RESEND_API_KEY` и `MAIL_FROM=Orluma <no-reply@auth.orluma.mariateslia.site>`.

Официальная документация: [проверка домена](https://resend.com/docs/dashboard/domains/introduction), [ключи API и ограничения доступа](https://resend.com/docs/dashboard/api-keys/introduction).

Вместо Resend можно подключить свой SMTP. Код не привязан к одному поставщику. Прежде чем приглашать команду, проверим доставку в реальные почтовые ящики, папку спама и восстановление пароля.

## Доступ к DNS mariateslia.site

Нужен вход в сервис, где управляются DNS домена. Добавим запись для `orluma`, которую покажет Render, и записи почтового поддомена из Resend. Сам сайт-портфолио продолжит работать на прежних записях. Значения DNS появятся после создания конкретных сервисов.

Пароли от аккаунтов и API-ключи в чат присылать не нужно: вводим их непосредственно в настройках сервиса или в приватном локальном `.env`.

## Что сейчас не требуется

Plaid, Stripe, отдельный сервис авторизации и хранилище банковских документов не нужны для текущего этапа. Подключение американских банков и импорт операций — следующий этап. Реальные выплаты и карты в первую финансовую версию не входят.

## Что остаётся перед приглашением реальных пользователей

Подтвердить тариф инфраструктуры → подключить Render и Resend → настроить DNS/HTTPS → зарегистрировать первый аккаунт → проверить реальную почту и восстановление → проверить роли вторым аккаунтом → настроить мониторинг и резервные копии → открыть ограниченную бету.
